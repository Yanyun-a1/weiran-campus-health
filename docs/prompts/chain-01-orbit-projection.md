## ① 用户原始 Prompt（逐字全文）

```text
上一版小球视图的球变成了椭圆，原因是 transform 顺序把球本身也旋转了。

这一轮废掉 CSS 的嵌套 3D 旋转，改成 JS 每帧计算投影。球永远是正圆，
只改变位置和大小。

════════════════════════════════
一、要删掉的东西
════════════════════════════════

1. 删掉 .orb-stage 的 transform-style: preserve-3d 和
   transform: rotateY(var(--ry)) rotateX(var(--rx))
2. 删掉 .orb-item 的
   transform: rotateY(var(--az)) rotateX(var(--el)) translateZ(var(--R))
3. 删掉 .orb-scene 的 perspective 和 perspective-origin
4. 删掉文字层的任何 rotateY / rotateX 反向抵消

CSS 3D 这一套全部不要了。球的位置和大小全部由 JS 算出来写进 transform。

════════════════════════════════
二、新的结构
════════════════════════════════

.orb-scene ── 定位容器
  position: relative，宽高 100%
  不需要 perspective

.orb-shell ── 透明大球（背景层，z-index 0）
  保持居中，border-radius: 50%
  桌面 720px，手机 96vw
  pointer-events: none

.orb-item × 3 ── 三个球（z-index 1）
  position: absolute
  left: 50%，top: 50%
  margin-left / margin-top 各为球半径负值
  transform: translate3d(var(--px), var(--py), 0) scale(var(--sc))
  transform-origin: center center
  will-change: transform

  ⚠️ 球自身绝对不能再有任何 rotateY / rotateX
  ⚠️ .orb-item 和它的父层都不能有 preserve-3d

.orb-rim ── 边缘光（z-index 3，pointer-events: none）

════════════════════════════════
三、JS 每帧计算（核心，按这个公式写）
════════════════════════════════

每个球记录三个固定参数（球面坐标）：

  食品健康：az = 0°，  el = 48°
  作息健康：az = 42°， el = -20°
  运动健康：az = -42°，el = -20°

半径：桌面 R = 250，手机 R = 140
相机距离：d = 1200

每帧根据当前 --ry / --rx，对每个球执行：

第一步 · 球面上的三维坐标
  x0 = R * cos(el) * sin(az)
  y0 = R * sin(el)
  z0 = R * cos(el) * cos(az)

第二步 · 绕 Y 轴旋转 ry
  x1 = x0 * cos(ry) + z0 * sin(ry)
  z1 = -x0 * sin(ry) + z0 * cos(ry)
  y1 = y0

第三步 · 绕 X 轴旋转 rx
  y2 = y1 * cos(rx) - z1 * sin(rx)
  z2 = y1 * sin(rx) + z1 * cos(rx)
  x2 = x1

第四步 · 透视投影
  k = d / (d - z2)
  px = x2 * k
  py = -y2 * k
  sc = k

第五步 · 写回 CSS 变量
  --px: px px
  --py: py py
  --sc: sc

同时根据 z2 设置深度效果（z2 越大越靠前）：
  t = (z2 + R) / (2 * R)，范围 0 到 1
  opacity  = 0.35 + 0.65 * t
  filter   = brightness(calc(0.65 + 0.35 * t)) blur(calc((1 - t) * 2.2px))
  z-index  = Math.round(t * 100)

用 requestAnimationFrame 节流，每帧只写这三个球的 CSS 变量和
opacity / filter / z-index，不要碰其他属性。

════════════════════════════════
四、拖动的角度
════════════════════════════════

pointerdown 记录起点，pointermove 计算 dx / dy：

  ry = clamp(-dx * 0.32, -42deg, 42deg)
  rx = clamp(dy * 0.20, -22deg, 22deg)

转成弧度再代入上面的公式（JS 里 Math.cos / Math.sin 要弧度）。

松手后 500ms 内 ry / rx 缓动回 0，cubic-bezier(.22,1,.36,1)，
缓动过程中也要持续跑 requestAnimationFrame 更新投影。

位移小于 8px 判定为点击，不触发旋转。

════════════════════════════════
五、透明大球外壳（现在太白，要改）
════════════════════════════════

现在外壳是一大团白色渐变，看起来像背景板不像玻璃球。改成：

背景压到几乎透明，只保留边缘一圈亮：
  radial-gradient(circle at 50% 50%,
    rgba(255,255,255,0) 0%,
    rgba(255,255,255,0) 52%,
    rgba(255,255,255,.04) 72%,
    rgba(255,255,255,.14) 86%,
    rgba(255,255,255,.30) 94%,
    rgba(255,255,255,.05) 100%)

内壁反光减弱：
  box-shadow:
    inset 0 0 60px rgba(255,255,255,.05),
    inset 0 -30px 70px rgba(255,255,255,.04)

顶部弧形高光（伪元素）：
  left 20%，top 6%，宽 42%，高 20%，border-radius 50%
  radial-gradient(ellipse at 50% 40%,
    rgba(255,255,255,.50), transparent 72%)
  filter: blur(16px)

底部反光（另一个伪元素）：
  left 26%，bottom 8%，宽 48%，高 16%，border-radius 50%
  radial-gradient(ellipse at 50% 60%,
    rgba(255,255,255,.22), transparent 70%)
  filter: blur(14px)

关键是：球心区域必须完全透明，能清楚看到背景色。只有边缘一圈和顶部
有亮，才像玻璃球。

════════════════════════════════
六、球体质感（保持上一版五层配方）
════════════════════════════════

.orb-skin 内层继续用：底部透光 + 主体渐变 + 内边缘暗环 + 顶部弧形高光
+ 边缘光，五层不变。

但因为现在球不再被旋转压扁，高光的位置会正确显示在左上角，效果会明显
比上一版好。

三色：
  食品健康 亮 #FFD9BE / 主 #FF8A5B / 暗 #C9442A
  作息健康 亮 #C7CFFF / 主 #6B7BE8 / 暗 #3B49A8
  运动健康 亮 #A8F0E8 / 主 #2AA79B / 暗 #16756C

════════════════════════════════
七、文字
════════════════════════════════

文字放在球内独立层，绝对居中，不参与任何 3D 变换。

它会跟着球的 scale 一起等比缩放，始终保持正圆比例、始终清晰。
深度 t < 0.25 时透明度降到 0.35。

字号：桌面 17px / 手机 15px，font-weight 600，白色，
text-shadow: 0 1px 2px rgba(0,0,0,.25)。

════════════════════════════════
八、点击分裂与中球层
════════════════════════════════

分裂动画和中球层逻辑保持上一版不变，只是中球也用同样的 JS 投影方式：

中球参数：R 桌面 175 / 手机 96，球径 桌面 200 / 手机 140，
az / el 与对应大球相同。

中球层同样支持拖动，同样隐藏顶栏切换器，左上角保留 44px 返回按钮。
点中球仍然滑出详情面板，这块完全不动。

════════════════════════════════
硬约束
════════════════════════════════

════════════════════════════════
```

## ③ 如何引导 AI 修复 Bug

**缺陷背景**：v5 用 CSS 嵌套 3D 旋转实现球面，transform 顺序把球体本身也旋转了，圆被拉成椭圆；同时渐变的 72%/86%/94% 停靠点落在可见圆之外，边缘光完全渲染不出来。

**人的引导动作**：用户在 Prompt 里直接写出根因「transform 顺序把球本身也旋转了」，并明确指定改法「废掉 CSS 的嵌套 3D 旋转，改成 JS 每帧计算投影，球永远是正圆，只改变位置和大小」，同时用「视觉风格、投影公式、分裂动画、事件逻辑一律不动」划定边界。这是「人做根因判断、AI 做实现」的典型分工。

**AI 的实际处理**：AI 实现后主动报告三处需要人决策的实现判断：① 拖动符号取 ry = dx*0.32 而非字面 -dx*0.32（实测字面值左右拖方向相反）；② 外壳渐变加 closest-side，否则停靠点全在可见圆外；③ 深度 opacity/filter 写在 .orb-skin、z-index 写在 .orb-item，避免与分裂动画抢同一属性。三处都给出了可验证的实测依据，而非直接改规格。
